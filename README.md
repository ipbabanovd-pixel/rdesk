# rdesk 2.0 — удалённый доступ через собственный сервер

rdesk — программа удалённого доступа к рабочему столу Windows из трёх частей:

| Часть | Для чего | Установщик |
|---|---|---|
| **rdesk server** | Центральный сервер: пароль, список компьютеров, пересылка сеансов | `rdesk-server-2.0.0-setup.exe` |
| **rdesk host** | Ставится на компьютер, к которому подключаются | `rdesk-host-2.0.0.msi` |
| **rdesk viewer** | Ваше окно со списком компьютеров и удалённым экраном | `rdesk-viewer-2.0.0.msi` |

Хосты и вьювер сами подключаются к серверу по исходящему TCP-соединению.
Входящие порты на компьютерах с host и viewer **открывать не нужно**. Порт
открывается только на сервере.

> **Разрешённое использование.** Программа предназначена для администрирования
> своих компьютеров или машин, к которым вам дали доступ. Установка host на чужой
> компьютер без согласия владельца запрещена. Хост постоянно показывает значок в
> области уведомлений и уведомляет о подключении вьювера — скрытого режима нет.

## Быстрый старт

### 1. Сервер

Запустите `rdesk-server-2.0.0-setup.exe` на компьютере, который будет
центральным сервером. Установка не требует прав администратора.

После установки откроется окно **rdesk server**. В нём:

1. Нажмите **«Копировать»** рядом с полем пароля — этот пароль понадобится
   хостам и вьюверу.
2. Порт по умолчанию — **7443**. Оставьте его, если нет причин менять.
3. Нажмите **«Открыть порт в брандмауэре»** (появится запрос UAC) или откройте
   входящий TCP-порт 7443 вручную.
4. Если сервер находится за роутером, пробросьте TCP 7443 с внешнего адреса
   роутера на локальный IP сервера.

> При первом запуске сервера Windows может показать окно «Безопасность Windows»
> с запросом доступа для Python. Нажмите **«Разрешить»** (достаточно частных
> сетей) или закройте окно и используйте кнопку «Открыть порт в брандмауэре».

Сервер можно свернуть в трей: он продолжит работать. При входе в систему он
запускается автоматически.

### 2. Компьютеры, к которым подключаемся (host)

На каждом удалённом компьютере запустите `rdesk-host-2.0.0.msi`. Установка
per-user, без администратора.

После установки откроется окно **rdesk host**:

1. Укажите **адрес сервера** (IP или DNS-имя; можно сразу `host:7443`).
2. Укажите **порт** — 7443, если не меняли.
3. Вставьте **пароль сервера**.
4. При необходимости измените имя компьютера в списке и включите
   «Только просмотр».
5. Нажмите **«Сохранить и подключиться»**.

Хост появится в списке вьювера. Он запускается при входе пользователя в систему
и виден в области уведомлений. Если компьютер за NAT, ничего пробрасывать на нём
не нужно — соединение исходящее.

> Компьютер должен быть в активном пользовательском сеансе: программа захватывает
> экран текущего рабочего стола. Заблокированный экран/экран входа Windows
> захватить нельзя.

### 3. Ваш компьютер (viewer)

Запустите `rdesk-viewer-2.0.0.msi`. После установки откроется окно входа:

1. Адрес сервера и порт.
2. Пароль сервера.
3. «Запомнить пароль» — чтобы не вводить его при следующем запуске.
4. **«Подключиться»**.

Слева появится список всех хостов, которые сейчас на связи. Выберите компьютер
и нажмите **«Подключиться»** (или дважды щёлкните по нему). Справа откроется
рабочий стол.

В сеансе доступны:

- управление мышью и клавиатурой;
- режим «только смотреть»;
- выбор качества (100/75/66/50/33 %) и FPS;
- полноэкранный режим по **F11**, выход — **Esc**;
- отправка текста из своего буфера обмена в буфер хоста;
- принудительное обновление экрана.

## Порты и сеть

| Где | Направление | Порт | Обязательно |
|---|---|---|---|
| Сервер | входящий TCP | **7443** | да |
| Host | исходящий TCP | 7443 | да |
| Viewer | исходящий TCP | 7443 | да |

Никакие другие порты rdesk не слушает. Порт задаётся в окне сервера; если вы его
изменили, укажите новый порт в хостах, вьювере, брандмауэре и пробросе роутера.

Если сервер в облаке — откройте 7443 в security group/файрволе облака. Если
сервер за NAT — нужен проброс порта или VPN. Адрес для хостов и вьювера — внешний
IP/DNS сервера, а не локальный адрес за роутером.

## Как это работает

```
                        ┌─────────────────────────────┐
     host ── исходящий ─┤  rdesk server :7443         │
     (за NAT)  TCP      │  пароль, список, relay      │
                        └──────────────┬──────────────┘
                                       │ исходящий TCP
                                  viewer (вы)
```

1. Хост подключается к серверу и регистрируется по постоянному `host_id`.
2. Вьювер входит на сервер по общему паролю и получает список хостов.
3. При подключении сервер выдаёт хосту и вьюверу **разные одноразовые токены**
   и сводит их каналы данных.
4. Внутри канала хост и вьювер выполняют обычное рукопожатие rdesk по паролю
   сервера. Сервер пересылает только зашифрованные байты и не видит экран.
5. Экран передаётся тайлами 64×64, только изменившиеся тайлы, со сжатием zlib.
   Ввод идёт через `SendInput`.

Пароль не отправляется открытым текстом: обе стороны доказывают его знание
HMAC-подписью (PBKDF2-HMAC-SHA256, 200 000 итераций). Управляющий канал и канал
сеанса шифруются SHAKE-256 + HMAC-SHA256.

Это не TLS-сертификат: сервер и клиенты аутентифицируют друг друга по паролю.
Используйте длинный пароль (сервер генерирует 20 символов) и не публикуйте порт
без необходимости.

## Безопасность и ограничения

- **64-битная Windows** (Windows 10/11 или Windows Server с рабочим столом).
  Проверено на Windows 11 x64.
- **Текущий пользовательский сеанс.** Заблокированный экран, экран входа и
  UAC-окна могут быть чёрными или недоступными для ввода.
- **Ctrl+Alt+Del** отправить нельзя — это защищённая комбинация Windows.
- **Программы, запущенные от администратора,** не принимают ввод, если host
  запущен без прав администратора (UIPI).
- **Нет звука, передачи файлов и запуска как службы.** Это осознанно: host
  работает в сеансе пользователя и виден в трее.
- **Один активный сеанс на хост** одновременно; вьюверов может быть несколько,
  каждый видит список.
- **Пароль хранится в файлах настроек** host/viewer/server в открытом виде —
  он нужен для вывода ключей. Ограничьте доступ к профилю пользователя.
- **Установщики не подписаны коммерческим сертификатом.** SmartScreen может
  показать предупреждение: «Подробнее» → «Выполнить в любом случае».
- **Смена пароля или порта сервера** отключает всех. После этого обновите
  настройки на каждом хосте и во вьювере.

## Где лежат настройки и журналы

Установка per-user, в профиль пользователя:

```
%LOCALAPPDATA%\rdesk\server\app\config\server.json
%LOCALAPPDATA%\rdesk\server\app\logs\server.log
%LOCALAPPDATA%\rdesk\host\app\config\host.json
%LOCALAPPDATA%\rdesk\host\app\logs\host.log
%LOCALAPPDATA%\rdesk\viewer\app\config\viewer.json
%LOCALAPPDATA%\rdesk\viewer\app\logs\viewer.log
```

Пароль сервера также показан (и копируется) в окне **rdesk server**.

## Удаление

- **host / viewer** — «Параметры → Приложения → Установленные приложения» →
  rdesk host / rdesk viewer → «Удалить». Либо `msiexec /x` с кодом продукта.
- **server** — ярлык `uninstall.cmd` в папке установки либо
  «Установленные приложения» → rdesk server.

При удалении MSI останавливает запущенный процесс и удаляет папку установки.

## Сборка из исходников

Нужны:

- Python 3.12 x64 (tkinter входит в стандартный установщик);
- .NET Framework 4.x (`csc.exe` есть в Windows);
- WiX Toolset 3.14. Скачайте `wix314-binaries.zip` со страницы
  `github.com/wixtoolset/wix3/releases` и распакуйте в `tools/wix314`
  (нужны `candle.exe`, `light.exe`, `heat.exe`, `WixUIExtension.dll`,
  `WixUtilExtension.dll`).

```bat
python packaging\build.py
```

Результат в `dist\`:

```
rdesk-server-2.0.0-setup.exe
rdesk-host-2.0.0.msi
rdesk-viewer-2.0.0.msi
```

Собрать только одну часть:

```bat
python packaging\build.py server
python packaging\build.py host
python packaging\build.py viewer
```

## Частые проблемы

**Вьювер пишет «Неверный пароль сервера».** Пароль сервера скопирован с
лишними пробелами или сервер перезапускался с новым паролем. Откройте окно
сервера, скопируйте пароль заново и вставьте в host/viewer.

**Компьютер не появляется в списке.** Проверьте на хосте статус «Подключено»,
адрес/порт сервера и что TCP 7443 доступен. Хост сам переподключается каждые
несколько секунд; при ошибке пароля ждёт дольше.

**Соединение с сервером отклонено.** Сервер не запущен, порт занят или закрыт
файрволом. На сервере должна быть строка «Сервер запущен на порту 7443».

**Вьювер видит чёрный экран.** Пользователь удалённого компьютера вышел из
системы, экран заблокирован или host запущен без нужных прав для окна
администратора.

**После смены пароля хосты отключились.** Это ожидаемо: обновите пароль в
настройках каждого хоста и в окне входа вьювера.
